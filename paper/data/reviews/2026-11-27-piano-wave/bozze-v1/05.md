TITLE: [0A-5] Golden fixture: decodifica dei file dati e caricamento nell'oracle
LABELS: wave-0,blocked

## Obiettivo
Trasformare i file di esempio di CardDemo in fixture verificate e caricarle nei file indicizzati dell'oracle GnuCOBOL, poi eseguire i batch di sola lettura per ottenere i primi output golden.

## Dipendenze e perimetro
- Dipende da: #3 (contratto dati), #4 (immagine oracle).
- Sorgenti legacy di riferimento: `app/data/ASCII/`, `app/data/EBCDIC/`, `app/jcl/` (`ACCTFILE`, `CARDFILE`, `CUSTFILE`, `XREFFILE`, `TRANFILE`, `TCATBALF`, `DISCGRP`, `TRANTYPE`, `TRANCATG`, `DUSRSECJ`, `READACCT`, `READCARD`, `READCUST`, `READXREF`), programmi `CBACT01C`, `CBACT02C`, `CBACT03C`, `CBCUS01C`.
- Cartelle coinvolte: `oracle/fixtures/`, `oracle/golden/read/`, `docs/legacy-map/fixture.md`.
- Fuori ambito: ciclo giornaliero (#6), loader Java (Wave 1).

## Specifica
- Decodifica guidata dal contratto dati di #3, con lo strumento adottato in #1, per ogni file di `ASCII/` e per i corrispondenti `EBCDIC/`.
- Vanno gestiti e documentati: terminatori di riga misti (`tcatbal.txt` e `trantype.txt` contengono sia CRLF sia LF, `trancatg.txt` CRLF), record più corti del `RECORDSIZE` (padding), segno overpunch sui campi zoned (per esempio `{` in `ACCT-CURR-BAL`), `USRSEC` disponibile solo in EBCDIC e in-stream in `DUSRSECJ.jcl`.
- Dove esistono entrambe le versioni, ASCII ed EBCDIC decodificati devono coincidere campo per campo; ogni differenza è elencata.
- Equivalente container di `DEFINE` + `REPRO`: caricamento nei file indicizzati con le chiavi del contratto.
- Esecuzione dei quattro batch di lettura; i loro output diventano `oracle/golden/read/`.

## Invarianti da preservare
- I file sotto `legacy/` non si toccano; le fixture sono derivate e rigenerabili.
- Nessun valore "riparato": un record anomalo resta anomalo e viene elencato.

## Criteri di accettazione (verificabili)
- [ ] `./oracle/run.sh fixtures --check` passa: numero di record per file, unicità delle chiavi primarie, totale di controllo per ogni campo numerico, confronto ASCII/EBCDIC.
- [ ] `./oracle/run.sh golden-read` rigenera `oracle/golden/read/` identico byte per byte a quello versionato.
- [ ] `docs/legacy-map/fixture.md` elenca per file: record, anomalie, decisioni di decodifica.
- [ ] Il diff tocca solo le cartelle dichiarate.

## Strategia di rollback
Revert della PR.

## Limiti per l'agente
- Se un batch di lettura non gira sotto GnuCOBOL, registrare l'errore e fermarsi con `needs-spec-update`; non modificarlo.
